01 / CONTEXT

El desafío no era solo transcribir audio. Era diseñar un producto confiable alrededor de una salida imperfecta.

PROBLEM

IA con incertidumbre

La salida del modelo no se trata como verdad final. Se conserva confianza por evento y se expone una revisión explícita para que el usuario pueda corregir.

SYSTEM

Tres límites claros

El navegador habla con Spring Boot; Spring actúa como API de producto; FastAPI queda como servicio interno de procesamiento. El frontend nunca llama directamente al módulo de IA.

PRODUCT

Revisión antes que automatismo

Las revisiones son inmutables, los conflictos no pisan trabajo previo y los artefactos descargables se vinculan a una revisión concreta.

04 / ENGINEERING DECISIONS

Decisiones pensadas para que el sistema pueda ser explicado, probado y corregido.

01

Revisiones inmutables y control de conflicto

Cada edición crea una nueva revisión completa. El cliente debe editar sobre la última revisión conocida; una base obsoleta devuelve conflicto en lugar de sobrescribir silenciosamente.

immutable history409 conflictstable IDs
02

Playback local con verificación del audio

El usuario vuelve a seleccionar su archivo original y el navegador valida tamaño y SHA-256 antes de crear un object URL local. El audio no se vuelve a subir para reproducirlo.

Web Cryptolocal object URLprivacy
03

Artefactos descargables con integridad

MIDI, MusicXML y SVG se describen con tipo, tamaño y digest. Spring y el navegador validan metadata, headers, longitud y SHA-256 antes de entregar una descarga.

MIDIMusicXMLSVGSHA-256
04

Cola durable sin sumar infraestructura innecesaria

Para el MVP, la cola usa PostgreSQL con claims, lease y reintentos acotados en lugar de introducir otro broker solo por arquitectura. El objetivo fue resolver ownership de trabajo de forma durable y explícita.

PostgreSQLSKIP LOCKEDworker
